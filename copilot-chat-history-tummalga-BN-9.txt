=== Turn 8 ===
User:
what is the secure way to to keep the username and pasd can we have it in app settings file only

Assistant:
No—don’t put a real SQL username or password in [appsettings.json](/C:/Users/Administrator/Downloads/IS7024_GroupProject/appsettings.json) if that file is committed to Git. Anyone with repository access could read it, and deleting it later doesn’t remove it from Git history.

**Recommended for Azure:** enable a managed identity for the app, grant that identity access to the Azure SQL database, and configure the connection string without a password, for example:

```json
"DefaultConnection": "Server=tcp:<server>.database.windows.net,1433;Database=<database>;Authentication=Active Directory Managed Identity;Encrypt=True;TrustServerCertificate=False;"
```

For **local development**, keep a SQL username/password in .NET User Secrets, not in `appsettings.json`:

```powershell
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "your-local-connection-string"
```

For deployment, Azure App Service settings or Key Vault can supply secrets as configuration overrides. `appsettings.json` can hold non-secret defaults and placeholders, but shouldn’t contain production credentials.
